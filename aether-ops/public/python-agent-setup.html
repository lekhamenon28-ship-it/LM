Onboard your existing Python agents

Your code runs inside your network, in your existing virtual environment. The hosted app stores registration, run input, status and JSON results. Agents may use LangGraph, CrewAI or another framework through a small Python wrapper.

  1. Register a private-network gateway in Infrastructure Integrations. If you already run a gateway, download the latest agent.py, replace the old version and restart it. Older gateways support only inventory.
  2. Keep your existing Python code and dependencies on the gateway machine. Use the Python executable from the agent's virtual environment in the command configuration.
  3. Adapt the agent to read a JSON object from stdin and print one JSON result to stdout. If it already follows that contract, register its script directly. For an existing function, use the wrapper below.
  4. Add an agents entry to your gateway configuration, using a local alias and an argv array. Restart the gateway after editing configuration.
  5. In Python Agents, click Onboard Python agent. Enter its name, description, gateway, matching alias and execution mode.
  6. Click Run agent, enter JSON input and approve the run if it can change infrastructure. Inspect the run from Run history after the gateway completes.

Wrap an existing Python function

Download python_entrypoint.py and the runnable example_agent.py. A callable accepts a dictionary and returns a JSON-serializable result; synchronous and asynchronous callables are supported.

def run(payload):
    # Call your existing agent here.
    result = existing_agent.invoke(payload)
    return {"summary": str(result)}

Set the module to your importable module name, such as my_existing_agent, and function to your callable name. Framework-specific initialization stays in your own module. Agent print statements are redirected away from the JSON result.

Gateway configuration

Merge this entry into your existing configuration alongside site and profiles. Paths below are examples; use your actual virtual environment and working directory.

"agents": {
  "my_python_agent": {
    "mode": "observe",
    "cwd": "/opt/my-agents",
    "command": [
      "/opt/my-agents/.venv/bin/python",
      "/opt/my-agents/python_entrypoint.py",
      "--module", "my_existing_agent",
      "--function", "run"
    ]
  }
}

The example configuration download includes a runnable my_python_agent entry. For a script that already reads JSON input, use "command": ["/path/to/python", "/path/to/agent.py"]. Commands are defined locally and never supplied by the hosted app. Input is passed on stdin.

Execution modes and limits

Use observe for observation agents. Agents that may make changes use change in both app and local configuration, plus "allowChanges": true locally. Each change-mode run requires administrator approval in the app. The gateway rejects mismatched modes. Mode selection does not sandbox Python or enforce read-only infrastructure access; use service-account permissions appropriate to your agent.

Runs currently have a 60-second process timeout, a two-minute delivery window and a 16,000-character limit for each JSON input and result. Nonzero exits, invalid JSON and timeouts appear as failed runs. Raw stderr is kept out of the hosted app. Review your own returned output before including secrets or sensitive data: workspace users can inspect results.

Disable cancels queued runs and prevents new runs. A process already started continues until completion or timeout. Long-running services, streaming, schedules and orchestration between agents are not part of this onboarding release.

Actual execution telemetry

The gateway measures execution duration automatically. Update agent.py to enable duration reporting. Token counts and costs cannot be inferred from an arbitrary Python result. Read actual usage from your model response and return it in this optional field:

{
  "summary": "Your actual agent result",
  "_aether_telemetry": {
    "inputTokens": 120,
    "outputTokens": 45,
    "cachedInputTokens": 0,
    "provider": "your provider",
    "model": "your actual model",
    "cost": 0.001,
    "currency": "USD"
  }
}

The numbers above illustrate the format only. Replace them with real usage; omit any field that is unknown. cost is the total amount for this execution in the stated currency. Token totals are not converted into cost using assumed prices. Agent-reported usage and cost are not independently verified against provider billing.

Report executions from your existing UI

Keep your current UI. Register its agent alias and gateway here, then call report_execution.py from that UI's backend after an agent run completes. It reports data only; it does not run your agent. Use a stable unique execution ID so retries do not double-count.

from report_execution import report_execution
import os

report_execution(
    "https://aether-ops-aiops.lekhamenon28.chatgpt.site",
    os.environ["AETHER_GATEWAY_TOKEN"],
    "my_python_agent",
    existing_run_id,
    {
        "ok": True,
        "input": actual_input,
        "output": actual_result,
        "durationMs": measured_duration_ms,
        "usage": actual_usage,
        "startedAt": actual_start_iso,
        "finishedAt": actual_finish_iso
    }
)

usage uses the same fields as _aether_telemetry above. Omit unknown usage or duration. startedAt and finishedAt are optional ISO timestamps; if omitted, the platform records receipt time. Results sent here are shared with workspace users. The API is POST /api/gateway/python/record authenticated with the gateway bearer token. The run is marked external-ui; no platform approval is implied for operations already executed elsewhere.
